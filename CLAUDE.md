# CLAUDE.md

Инструкции для Claude Code при работе с этим репозиторием.

## Проект

**SysDesign Flow** — визуальный тренажёр по проектированию высоконагруженных систем.
Короткое техническое имя (папка, репозиторий, пакет) — `sd-flow`; продуктовое имя в любом
пользовательском тексте — **SysDesign Flow**.

**Статус: проектирование.** Кода ещё нет, репозиторий содержит только спецификацию.

| Документ | Содержание |
|---|---|
| `PRD.md` | Главный документ: цели, персоны, режимы, функциональные требования, UX, дорожная карта, риски |
| `docs/01-components.md` | Каталог строительных блоков: 14 групп, 129 типов (44 в MVP), параметры каждого |
| `docs/02-simulation.md` | Модель симуляции: ёмкость, очереди, latency, кэш, мультирегион, аномалии согласованности, стоимость, константы |
| `docs/03-connections.md` | Семантика связей, профили вызова, визуальное кодирование трафика |
| `docs/04-challenges.md` | Режим заданий, алгоритм приёмки, рубрика, линтер, каталог задач |
| `docs/05-architecture.md` | Техническая архитектура, структура репозитория, ADR |

Базовый проект-донор по визуалу, флоу и стеку — [`dsp-flow`](https://github.com/Alexxtn105/dsp-flow).

## Работа с документацией

- Язык документации — русский, технические термины оставляются в оригинале (RPS, p99, fanout, SLO).
- Все числа приводятся с единицами измерения и в человекочитаемом виде: `101 PB/сут`, `9.4 Тбит/с`.
- Любая формула должна быть объяснима: символы расшифрованы, значения по умолчанию указаны.
- Расчётные примеры проверяются арифметически перед публикацией.
- Изменение модели симуляции влечёт синхронную правку `docs/02-simulation.md` и, если затронуты
  параметры блоков, — `docs/01-components.md`.
- Продуктовые решения фиксируются в `PRD.md` §13.2 (таблица решений) и в ADR
  `docs/05-architecture.md` §13, а не в истории переписки.
- ASCII-макеты в документах выровнены по символам: при правке текста внутри рамки сохранять
  длину строки, иначе рамка разъезжается.

## Код (когда появится)

- TypeScript strict с первого дня, ESLint 9 flat config, Vitest.
- **Комментарии в коде запрещены** — код должен быть самодокументируемым за счёт имён
  и структуры. Пояснения идут в документацию, а не в исходники.
- Ядро симуляции — чистые функции без зависимостей от React, DOM и i18n.
- Никакого `Math.random()` и `Date.now()` в движке: только seeded PRNG и переданное время,
  иначе ломается детерминизм приёмки заданий.
- Архитектурные решения принимаются в соответствии с ADR из `docs/05-architecture.md` §13;
  отклонение от ADR требует правки самого ADR.
