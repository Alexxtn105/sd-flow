# 08. Гайд: свой блок (плагин)

Приложение к [PRD.md](../PRD.md). Пошаговый рецепт: как добавить в каталог новый тип блока — от
решения «что это вообще за блок» до зелёных тестов и справки в интерфейсе.

Смежные документы: контракт и мотивация — [docs/05-architecture.md](05-architecture.md) §3,
существующие 127 блоков и их параметры — [docs/01-components.md](01-components.md), формулы
ёмкости, очередей и счёта — [docs/02-simulation.md](02-simulation.md), порты и семантика связей —
[docs/03-connections.md](03-connections.md).

## 1. Что здесь называется плагином

В `dsp-flow`, откуда взяты визуал, флоу и палитра, единица расширения — **плагин**: модуль с
описанием блока и функцией обработки сигнала, зарегистрированный в `PluginRegistry`. В SysDesign
Flow ему соответствует **тип компонента** в `ComponentRegistry`: тот же реестр, те же группы, то же
правило «блоки — это данные, а не правки ядра», но вместо `processor.process()` у блока стоит
модель из чистых функций — `serviceSec`, `capacity`, `cost` и ещё пять необязательных.

Дальше в тексте «плагин» и «блок» — одно и то же.

**Плагин компилируется в бандл.** Загрузки плагинов со стороны — из файла, по ссылке, из
`localStorage` — нет, и это осознанно:

* **детерминизм приёмки.** Задание судится в канонических условиях
  ([docs/04-challenges.md](04-challenges.md) §4.0); блок, подгруженный извне, сделал бы вердикт
  невоспроизводимым;
* **расчёт живёт в воркере.** `src/workers/simulation.worker.ts` вызывает `initComponents()` сам,
  на верхнем уровне модуля, и держит **собственный** экземпляр реестра. Регистрация «в рантайме на
  стороне интерфейса» до расчёта просто не доедет;
* **недоверенный ввод не может быть кодом.** Ровно по этой причине в авторских заданиях нет
  `custom`-предиката ([docs/04-challenges.md](04-challenges.md) §12), и по ней же нет «плагина из
  текстового поля».

Реестр это закрепляет: `initComponents()` в конце вызывает `registry.freeze()`, после чего
`register()` бросает исключение. Расширение каталога = правка исходников + сборка.

**Что даёт регистрация.** Один объект `ComponentDefinition` включает блок сразу везде:

| Где | Что появляется |
|---|---|
| Палитра | Карточка в секции своей группы, поиск по имени, идентификатору и тексту справки |
| Холст | Узел с иконкой, цветной гранью группы, портами и правилами совместимости |
| Инспектор | Поля параметров по секциям, единицы, диапазоны, знак `$` у платящих |
| Движок | Участие в решателе, очередях, стоимости, хранилище, ходе времени, сценариях |
| Задания | Тип доступен в требованиях (`to: { type: … }`), в ограничениях и в приёмке |
| Авторский YAML | Тип можно ставить в `starter.nodes[].type` ([docs/09-scheme-yaml.md](09-scheme-yaml.md)) |
| Справка | Окно `?` с ёмкостью, счётом, практиками и ошибками |

## 2. Где живёт код

```
src/engine/
├── ComponentRegistry.ts          ← синглтон-реестр: register / registerGroup / freeze
├── initComponents.ts             ← порядок групп и сборка всех массивов
├── ports.ts                      ← совместимость портов по протоколам
├── edgeDefaults.ts               ← форма ребра и профили вызова по умолчанию
├── types/component.ts            ← ComponentDefinition, ComponentModel, контексты
├── sim/resources.ts              ← defineModel и билдеры ограничителей ёмкости
└── components/
    ├── _shared/params.ts         ← num / bool / choice / text / defineComponent
    └── <группа>.ts               ← сами блоки, один модуль на группу
```

Новый блок — это **правка одного модуля группы** (`src/engine/components/platform.ts` и т. п.) плюс
записи в словарях локалей. Трогать ядро не нужно: ни решатель, ни инспектор, ни палитра о
конкретных блоках не знают.

## 3. Шаг 1. Паспорт блока

Дальше сквозным примером идёт **`sms-gateway`** — блок, которого в каталоге нет: шлюз рассылки SMS
рядом с существующим `email-smtp`. Он выбран потому, что показывает весь конвейер на маленькой
модели: квота провайдера как ограничитель, аренда инстансов и плата за сообщения как две статьи
счёта.

```ts
const smsGateway = defineComponent({
    id: 'sms-gateway',
    group: 'platform',
    shape: 'node',
    wave: 'v2',
    icon: 'sd-notification',
    ports: DISPATCH_PORTS,
    defaultParams: smsGatewayDefaults,
    paramSchema: { /* …по записи на каждый ключ defaultParams */ },
    model: smsGatewayModel,
    managed: true,
    helpId: 'sms-gateway',
});
```

Обязательны девять полей: `id`, `group`, `shape`, `wave`, `icon`, `ports`, `defaultParams`,
`paramSchema`, `helpId`. Отсутствие любого — исключение при старте с именем поля в тексте.

| Поле | Чем является | На что влияет |
|---|---|---|
| `id` | Стабильный идентификатор в kebab-case | Ключ локалей, справки и **сохранённых схем**. Переименование ломает чужие сохранённые схемы и требует миграции (`services/schemeMigrations.ts`) |
| `group` | Одна из 14 групп | Модуль-файл, секция палитры, цвет грани, а ещё умолчания движка: смесь и размеры payload у нового ребра (`edgeDefaults.mixFor`), оплата потока логов группой `observability` |
| `shape` | Роль на холсте, см. таблицу ниже | Тип узла React Flow, участие в расчёте |
| `wave` | `mvp` / `v1` / `v2` | Бейдж в справке; тест каталога требует, чтобы волна была из этих трёх |
| `icon` | Имя иконки, всегда с префиксом `sd-` | Рисунок на карточке и на узле. Иконка обязана быть нарисована в `SdIcons.tsx`; вендорских логотипов быть не может (ADR-10) |
| `helpId` | Ключ раздела справки | Тест каталога требует `helpId === id`, отдельного пространства имён нет |
| `managed` | Необязательный флаг «избыточность держит провайдер» (решение **D5**) | Блок не попадает в SPOF (`sim/availability.ts`), не штрафуется за низкую утилизацию и умножается на `managedMultiplier` профиля цен |
| `model` | Необязательный слот модели | Без него блок не считается — см. §6 |

**`shape` — пять значений, и они не косметика:**

| `shape` | Сколько в каталоге | Что это значит |
|---|---|---|
| `node` | 108 | Обычный узел. **Только он несёт трафик**: решатель, очереди, стоимость, ход времени, кластеры и сценарии фильтруют узлы именно по `shape === 'node'` |
| `container` | 4 | Контейнер (`region`, `az`, `vpc`, `k8s-cluster`): рисуется как группа, участвует в размещении и RTT |
| `probe` | 11 | Измерительное окно: показывает уже посчитанное, ресурсов не потребляет, денег не стоит |
| `policy` | 1 | Политика (`multi-region-policy`): узел на холсте, читается движком как настройка, трафика не несёт |
| `link` | 3 | Канал (`internet`, `link-cross-az`, `link-cross-region`): в палитре скрыт, `addComponent` такой тип отклоняет |

Если вы добавляете обычный сервис, базу или очередь — это `node`, и дальше весь гайд про него.

## 4. Шаг 2. Параметры

Параметры блока описываются **дважды и синхронно**: значения по умолчанию и схема полей.

```ts
const smsGatewayDefaults = {
    messagesPerEvent: 1,
    messagesPerSec: 200,
    instances: 2,
    concurrency: 64,
    serviceTimeMs: 120,
    deliveryReceipts: true,
    retryPolicy: 'once',
    availability: 0.999,
    costPerInstanceHour: 0.08,
    costPerThousandMessages: 4,
};
```

```ts
paramSchema: {
    messagesPerEvent: num('behaviour', { min: 1, max: 1000, realistic: { min: 1, max: 10 } }),
    messagesPerSec: num('capacity', { unitKey: 'rps', min: 1, max: 100000 }),
    instances: num('scale', { min: 1, max: 100 }),
    concurrency: num('capacity', { min: 1, max: 100000 }),
    serviceTimeMs: num('performance', { unitKey: 'ms', min: 1, max: 60000, step: 0.1 }),
    deliveryReceipts: bool('behaviour'),
    retryPolicy: choice('behaviour', ['none', 'once', 'exponential-backoff']),
    availability: num('reliability', { min: 0.9, max: 0.99999, step: 0.0001 }),
    costPerInstanceHour: num('cost', { unitKey: 'usd', min: 0, max: 1000, step: 0.001 }),
    costPerThousandMessages: num('cost', { unitKey: 'usd', min: 0, max: 100, step: 0.01 }),
}
```

Четыре вида полей, все из `components/_shared/params.ts`:

| Хелпер | Вид | Что принимает |
|---|---|---|
| `num(section, options)` | `number` | `unitKey`, `min`, `max`, `step`, `realistic: { min, max }` |
| `bool(section)` | `boolean` | — |
| `choice(section, options)` | `enum` | Список допустимых строк |
| `text(section)` | `text` | — |

**Секция** определяет, в какую группу полей инспектор поставит параметр. Порядок секций задан не
типом, а `utils/paramSections.ts`: `scale` → `performance` → `capacity` → `behaviour` →
`consistency` → `data` → `reliability` → `topology` → `cost`. Заголовки берутся из `common.json`
(`section.*`).

Правила, которые стоят денег, если их нарушить:

* **Ключи `defaultParams` и `paramSchema` совпадают один в один.** Реестр проверяет это при
  регистрации и падает с текстом «параметр "x" не описан в paramSchema» или «в paramSchema описан
  несуществующий параметр "x"». Опечатка ловится при старте, а не при первом открытии инспектора.
* **`min`/`max` — границы, за которыми расчёт бессмысленный; `realistic` — рабочий диапазон.**
  Инспектор красит выход за первое красным, за второе — подписью «так не бывает».
* **Нет `step` — параметр счётный.** Инстансы, шарды, брокеры, партиции и реплики объявляются без
  шага: ползунок и стрелки тогда ходят по целым, а введённое руками `3.5` округляется
  ([docs/01-components.md](01-components.md) §2.0). Шаг объявляют там, где дробное значение
  осмысленно: `0.01` у долей, `0.25` у `cpuCores` (это `500m` из Kubernetes).
* **Значение по умолчанию обязано попадать в свои границы**, а у `enum` — в список вариантов. Это
  проверяет `tests/engine/catalog.test.ts`.
* **Блок, за который платят почасово, обязан говорить, сколько его** — параметром вида `instances`,
  `nodes`, `brokers` ([docs/01-components.md](01-components.md) §2.1). Иначе счёт нельзя ни
  посчитать, ни объяснить.
* **`unitKey`** — ключ единицы измерения (`ms`, `sec`, `rps`, `gb`, `usd`, …), она рисуется у поля
  и в справке.

### 4.1. Имена, которые движок читает сам

Большая часть параметров существует только для модели блока — как их назвать, решает автор. Но есть
имена, которые движок читает **напрямую, минуя модель**, и назвав параметр так, вы включаете
готовое поведение (а назвав иначе — не включаете). Самые ходовые:

| Имя | Кто читает и что делает |
|---|---|
| `instances`, `concurrency`, `concurrencyPerInstance`, `cpuCores` | Решатель: размер пула приборов и ожидание зависимостей |
| `serviceTimeSigma` | Разброс времени обслуживания: очереди, Monte-Carlo задержек, ход времени |
| `timeoutMs`, `queueLimit` | Отсечка по таймауту и предел глубины очереди |
| `avgRequestKb`, `avgResponseKb` | Посев payload на исходящих рёбрах (`applySourcePayload`) |
| `provisionedIops` | Оплата выделенных IOPS сверх бесплатных 3000 (`sim/provisioned.ts`) |
| `costPerGbEgress` | Своя ставка egress вместо ставки профиля цен |
| `logLinesPerRequest`, `logBytesPerLine` | Поток логов, его объём и счёт за него |
| `rowSizeBytes`, `documentSizeBytes`, `messageSizeBytes` | Размер записи для модели хранения |
| `idempotent`, `idempotencyRequired` | Ключи идемпотентности и аномалия дублей |
| `concurrencyControl` + `rowCount` / `uniqueKeys` / `documentCount` / `itemCount` / `keyCount` | Конкуренция за ключ: повторы и сериализация (`sim/contention.ts`) |
| `hitRatioMode`, `hitRatioOverride` | Режим расчёта попаданий в кэш |
| `availability`, `replicaLagMs`, `replicaLagSigma`, `quorumN`, `quorumR`, `quorumW` | Девятки, лаг реплик, кворум |

Отдельное соглашение — **пресеты инстанса** (`engine/instancePresets.ts`): «размерными» считаются
`cpuCores`, `memoryGb`, `bufferPoolGb`, `networkMbps`, `costPerInstanceHour`. Если блок объявляет
хотя бы два из них положительными числами, в инспекторе появляется переключатель XS–XL, который
масштабирует их разом (0.25× / 0.5× / 1× / 2× / 4×, `cpuCores` округляется до целого). Отсюда
правило для дефолтов: **значения по умолчанию — это и есть «M»**, остальные размеры машины
получаются из них умножением, поэтому дефолты стоит подбирать как середину линейки, а не как
крайний случай.

## 5. Шаг 3. Порты

Порт — это не «точка на картинке», а объявление протокола и роли. Совместимость рёбер считается
пересечением протоколов, а форма нового ребра — ролью выходного порта.

```ts
const DISPATCH_PORTS: PortSpec = {
    in: [{ id: 'in', protocols: ['http', 'grpc'], role: 'serve' }],
    out: [{ id: 'out', protocols: ['http', 'grpc', 'internal'], role: 'call' }],
};
```

**Роли** (`PortRole`): `serve` — принимает синхронный вызов; `call` — вызывает сам;
`replicate` — репликация; `emit` — отдаёт события; `consume` — потребляет события;
`observe` — телеметрия; `attach` — прикрепление пробы.

**Протоколы** (`Protocol`): `http`, `grpc`, `ws`, `dns`, `sql`, `nosql`, `redis`, `search`, `olap`,
`kafka`, `amqp`, `sqs`, `s3`, `stream`, `telemetry`, `internal`.

Что из этого следует:

* **Связь разрешена, если у выходного и входного портов есть общий протокол** —
  `ports.isConnectionAllowed`, а первый общий протокол становится протоколом ребра.
  Никакой матрицы «кто с кем» в коде нет: матрица из [docs/03-connections.md](03-connections.md) §4
  — это следствие объявленных портов.
* **Роль выходного порта задаёт форму ребра** (`edgeDefaults.shapeFor`): `replicate` →
  `kind: 'replication'` с профилем `transfer`; `emit` → `kind: 'async'`, `pull: true` и профиль
  `consume`; иначе смотрится группа приёмника — `messaging` даёт `publish`, `observability` —
  `transfer`, всё прочее получает пару профилей `read`/`write`.
* **Смесь и размеры payload по умолчанию зависят от группы приёмника**: `cache` — 95 % чтений,
  200 → 2000 байт; `storage` — 80 % чтений, 1000 → 500 000 байт; прочие хранилища — 90 %,
  300 → 4000 байт; остальные блоки — 90 %, 500 → 2000 байт.
* **Хотите принимать события брокера — объявите второй вход с ролью `consume`.** Так устроены
  `service`, `monolith`, `bff`, `serverless`: `serve` для `http`/`grpc`, `consume` для
  `kafka`/`amqp`/`sqs`/`stream`. Смешивать их в одном порту нельзя — сервис не обслуживает Kafka как
  сервер, он её потребляет.
* **У блока-узла должен быть хотя бы один порт** — иначе падает `tests/engine/catalog.test.ts`.

## 6. Шаг 4. Модель

Блок без модели не считается: решатель поставит ему `boundBy: 'unmodelled'`, и в отчёте появится
находка с тем же кодом. Для `probe`, `policy`, `link` и клиентских блоков это норма, для всего
остального — недоделка, и `tests/engine/capacity-coverage.test.ts` её ловит.

Модель пишется **не руками**, а через `defineModel` из `sim/resources.ts`: он сворачивает список
ограничителей в `capacity`, отбрасывает `null` и бесконечности, а имя самого узкого ресурса кладёт
в `boundBy`.

```ts
const smsGatewayModel = defineModel<typeof smsGatewayDefaults>({
    serviceSec: (ctx) => smsServiceSec(ctx.params),
    resources: (ctx) => [
        quotaBound('provider-quota', ctx.params.messagesPerSec / ctx.params.messagesPerEvent),
        littleLaw('concurrency', ctx.instances * ctx.params.concurrency, smsServiceSec(ctx.params)),
    ],
    cost: (ctx) =>
        totalCost({
            compute:
                ctx.instances * ctx.params.costPerInstanceHour *
                HOURS_PER_MONTH * ctx.regionCostMultiplier,
            storage: 0,
            network: 0,
            requests: smsThousandsPerMonth(ctx) * ctx.params.costPerThousandMessages,
        }),
    availability: (params) => params.availability,
});
```

Арифметика выносится в именованные функции (`smsServiceSec`, `smsThousandsPerMonth`) — внутри списка
ресурсов её быть не должно. Типизация идёт через `typeof smsGatewayDefaults`: тогда опечатка в
имени параметра падает на компиляции.

**Контекст.** На вход приходит `NodeContext`: `nodeId`, `params`, `instances` (уже после
автоскейлинга), `lambda` (входящий поток, rps), `readShare`/`writeShare`, `requestBytes`/
`responseBytes`, `blockingSec` (ожидание зависимостей, которое решатель уже посчитал). У `cost`
контекст шире (`pricing`, `storageGb`, `egressGbMonth`, `regionCostMultiplier`), у `storage` —
тоже (`writeRps`, `recordBytes`, `horizonDays`).

**Билдеры ограничителей** — только они, а не арифметика на месте: каждый сам заполняет `explain`
с формулой и подставленными значениями, а объяснимость проверяется тестом.

| Билдер | Формула | Когда |
|---|---|---|
| `littleLaw(res, servers, S)` | `servers / S` | Классический прибор: воркеры, потоки, соединения на обслуживании |
| `explicitRps(res, instances, rpsPerInstance)` | `instances × rpsPerInstance` | Объявленный потолок на инстанс |
| `connectionBound(res, maxConn, connPerReq, S)` | `maxConnections / connectionsPerRequest / S` | Пул соединений |
| `iopsBound(res, iops, perRead, perWrite, r, w)` | `iops / (r × perRead + w × perWrite)` | Диск с выделенными IOPS |
| `vendorUnitBound(res, rcu, wcu, perRead, perWrite, r, w)` | Взвешенная единица вендора | RCU/WCU у DynamoDB-подобных |
| `weightedUnitBound(res, formula, inputs, …)` | Общий случай «цена чтения ≠ цена записи» | Свой взвешенный ресурс |
| `bandwidthBound(res, mbps, bytesPerRequest)` | `mbps × 10⁶ / 8 / bytes` | Полоса сети |
| `partitionBound(res, partitions, rpsPerPartition)` | `partitions × rpsPerPartition` | Партиции и шарды |
| `quotaBound(res, quotaRps)` | `quotaRps` | Жёсткая квота провайдера |
| `memoryResidencyBound(res, memoryGb, perRequestGb)` | `memoryGb / perRequestGb` | Данные обязаны помещаться в память |
| `resourceLimit(res, value, formula, inputs, unit?)` | Любая | Когда ни один билдер не подходит: формулу пишете вы |

Ограничитель можно вернуть `null` — он просто выпадет из списка. `occupancyBound` **не для
моделей**: ожидание зависимостей накладывает сам решатель (`sim/solver.ts`).

**Имя ресурса — это ключ локали.** Каждое имя (`provider-quota`, `concurrency`, …) обязано быть
переведено в `locales/{ru,en}/common.json` в секцию `bound.*`, иначе
`tests/engine/capacity-coverage.test.ts` красный. Смотреть на уже существующие имена полезно:
чем меньше синонимов, тем понятнее игроку.

**Что проверяет тест покрытия** при трёх смесях (100/0, 80/20, 0/100 чтение/запись):

* у каждого блока-узла не из группы `clients` есть `model`;
* `capacity > 0`, список ограничителей непуст, все значения конечны;
* у каждого ограничителя непустая формула и непустой набор входов;
* `serviceSec(ctx) > 0`.

## 7. Шаг 5. Деньги

Правила счёта разобраны в [docs/02-simulation.md](02-simulation.md) §9.1; здесь — то, что обязан
сделать автор блока.

* **Каждый объявленный параметр вида `costPer*` обязан участвовать в счёте.** Объявить ценник и не
  использовать его нельзя — `tests/engine/cost-coverage.test.ts` сравнивает счёт схемы до и после
  изменения ценника (решение **D6**).
* **Купленная ёмкость не бывает бесплатной** (решение **D7**). `tests/engine/cost-drivers.test.ts`
  удваивает каждую арендуемую единицу из списка семнадцати имён — `instances`, `nodes`, `shards`,
  `readReplicas`, `replicas`, `consumerGroups`, `popCount`, `gpuCount`, `brokers`, `workers`,
  `regionServers`, `publicIps`, `provisionedConcurrency`, `parallelism`, `gateways`, `bookies`,
  `anycastPops` — и падает, если ёмкость выросла, а счёт нет. Исключения перечислены в самом тесте
  вместе с причиной; новое исключение туда добавляется только с внятным обоснованием.
* **Размер машины отдельно не тарифицируется.** `cpuCores`, `memoryGb`, `bufferPoolGb`,
  `heapGb`, `networkMbps` уже сидят в `costPerInstanceHour` и двигаются пресетом инстанса
  (`engine/instancePresets.ts`). Начислять за них — значит брать за машину дважды.
* **Объявленный диск — это потолок, а не счёт.** Платят за фактический объём данных, который
  вернул слот `storage`.
* **Надбавки начисляет движок** (`sim/cost.ts`, функция `withSurcharges`), и дублировать их в
  модели нельзя: выделенные IOPS сверх бесплатных 3000 → в `storage`; премия за `managed` умножает
  `compute`, `storage` и `requests`, но **не** `network`; бэкапы, логи и ключи идемпотентности →
  в `storage`; egress → в `network` по ставке `costPerGbEgress` блока или профиля цен. Узел без
  `model.cost` надбавки всё равно получает.
* **Региональный множитель — на стороне блока.** `ctx.regionCostMultiplier` приходит в контекст,
  но умножить на него свою почасовую аренду обязана сама модель (см. пример выше).
* Стоимость собирается `totalCost({ compute, storage, network, requests })` — сумма считается сама.
  Блок без собственного счёта возвращает `emptyCost()`; единственный такой в каталоге —
  `local-cache`, и это исключение названо в тесте.

Список платящих параметров нигде не пишется руками: `sim/costDrivers.ts` ставит блок в синтетические
условия (5000 rps, смесь 80/20, 2 КБ запрос и 20 КБ ответ, 1000 ГБ egress за месяц) и меняет каждый
параметр по очереди — число вдвое в пределах границ, флаг на противоположный, перечисление на другой
вариант — а затем смотрит, какие статьи счёта поехали. Отсюда знак `$` в инспекторе и в карточке
параметров на холсте, и раздел «Что двигает счёт» в справке. Это же означает: **если ваш параметр
должен стоить денег, но знак `$` не появился — модель его не учитывает**, и это баг блока, а не
интерфейса.

## 8. Шаг 6. Необязательные слоты

Кроме `serviceSec`, `resources` и `cost` у модели есть пять слотов, каждый включает свой кусок
движка:

| Слот | Возвращает | Зачем |
|---|---|---|
| `storage(ctx)` | `{ totalGb, growthGbDay, memoryGb, explain[] }` | Объём данных, рост, бэкапы и счёт за хранение; проба хранилища и требование `storage` в заданиях |
| `cache(ctx)` | `CacheProfile` (уникальные ключи, `zipfAlpha`, размер записи, ёмкость, TTL) | Модель попаданий по Ципфу ([docs/02-simulation.md](02-simulation.md) §6) |
| `availability(params)` | Долю девяток | Расчёт доступности схемы и SPOF |
| `quorum(params)` | Размер кворума | Согласованность и поведение при разрыве |
| `autoscale(ctx)` | Число инстансов | Автоскейлинг в стационаре и лаг скейлера в transient |

Слоты необязательны ровно в том смысле, что без них блок работает — просто соответствующий кусок
модели про него молчит.

## 9. Шаг 7. Регистрация

1. Добавьте блок в экспортируемый массив модуля группы:

```ts
export const platformComponents: ComponentDefinition[] = [
    /* … */
    smsGateway,
] as unknown as ComponentDefinition[];
```

2. Если группа новая — впишите её в `GroupId` (`types/component.ts`), в `GROUP_ORDER` и в
   `registerAll` внутри `initComponents.ts`, добавьте перевод в `locales/{ru,en}/groups.json` и
   цветную грань `.sd-node-<группа>` с `border-left-color` в `SdNode.css` (её проверяет
   `tests/components/nodeAccent.test.ts`). Порядок в `GROUP_ORDER` — это порядок секций палитры, и
   он сверяется с документом каталога.

Существующей группе больше ничего не нужно: массив уже подключён.

`initComponents()` вызывается из двух мест: `src/main.tsx` (в `try/catch` — упавшая регистрация
показывает экран «Ошибка инициализации каталога блоков») и с верхнего уровня
`src/workers/simulation.worker.ts`. У воркера **свой** экземпляр реестра, поэтому блок, попавший
только в интерфейс, в расчёте отсутствует; повторный вызов — no-op из-за `isFrozen()`.

## 10. Шаг 8. Локали и справка

Без записей в словарях блок появится в палитре с сырым идентификатором, а тесты покрытия локалей
станут красными. Нужны:

| Файл (оба языка) | Ключ | Содержание |
|---|---|---|
| `blocks.json` | `sms-gateway` | Имя блока в палитре и на узле |
| `params.json` | Каждое новое имя параметра | Подпись поля в инспекторе |
| `params.json` → `enum` | Каждое новое значение перечисления | Подпись варианта |
| `params.json` → `units` | Только для нового `unitKey` | Единица измерения у поля |
| `groups.json` | Только для новой группы | Имя секции палитры |
| `common.json` → `bound` | Каждое новое имя ресурса | «Упирается в …» |
| `help.json` | `sms-gateway` | `summary`, `capacity`, `practices` (≥ 2), `pitfalls` (≥ 2) |
| `hints.json` | Каждое новое имя параметра | Подсказка с единицей измерения |

Про справку отдельно (ADR-15, [docs/01-components.md](01-components.md) §16):

* `summary` — «что это и когда ставить», 2–3 предложения. По этому тексту работает поиск в палитре,
  поэтому в нём стоит называть вещи своими именами;
* `capacity` — «во что упирается», словами и с числами;
* `practices` — 3–5 практик **с конкретными значениями**; `pitfalls` — 2–4 антипаттерна;
* `hints.json` ключуется **именем параметра, а не блока**: подсказка общая для всех блоков, где
  параметр встречается, поэтому пишется вендор-нейтрально и обязательно с единицей измерения;
* `help.json` и `hints.json` догружаются лениво (`services/referenceBundle.ts`) и в главный бандл
  не попадают.

Если блок появляется в поставляемой схеме (демо, стартовая схема задания, эталон), у **узла** ещё
нужна роль в `locales/{ru,en}/nodes.json` — подписи узлов ключуются идентификатором узла, а не
типом блока (ADR-14).

Каталог — это цифры в трёх местах, и они обязаны сойтись:

## 13. Частые ошибки

| Симптом | Причина |
|---|---|
| Приложение падает при старте с именем параметра | Разошлись `defaultParams` и `paramSchema` |
| Блок есть в палитре, но в расчёте «не считается» | Нет `model`; `boundBy` равен `unmodelled` |
| Ребро к блоку не рисуется | Нет общего протокола у портов; проверьте `ports.isConnectionAllowed` |
| Ребро приехало не той формы (sync вместо async) | Роль выходного порта: `emit` даёт async и `pull`, `call` — sync |
| Тест `capacity-coverage` красный на имени ресурса | Забыт перевод в `common.json` → `bound` |
| Тест `cost-drivers` красный | Параметр поднимает ёмкость и не поднимает счёт |
| В инспекторе у параметра нет знака `$`, хотя он должен стоить денег | Модель его не учитывает — знак измеряется, а не проставляется |
| Блок посчитан в интерфейсе, но не в приёмке задания | Новая точка входа в движок недостижима из воркера |
| Ползунок инстансов выдаёт дробные | У счётного параметра объявлен `step` |

## 14. Чего плагин не может

* **Загружаться со стороны.** Реестр заморожен после `initComponents()`; расширение — это правка
  исходников и сборка (§1).
* **Быть нечистой функцией.** В движке запрещены `Math.random()` и `Date.now()`: только seeded PRNG
  (`sim/rng.ts`) и переданное время, иначе ломается детерминизм приёмки. Идентификаторы выдаёт
  `engine/ids.ts`.
* **Ходить в стор, DOM, i18n или к соседним узлам.** Модель — чистая функция от контекста; всё, что
  ей нужно знать о соседях, решатель уже сложил в `lambda`, `blockingSec` и доли чтения/записи.
* **Носить вендорский логотип** (ADR-10): иконка — родовая метафора.
* **Комментировать себя в коде.** Пояснения идут в справку и в эти документы, а не в исходник.
